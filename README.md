# Athenaion Light

[公開サイト](https://sickness8484.github.io/athenaion-light/) · [軽さ優先](https://sickness8484.github.io/athenaion-light/?profile=fast)

[Leonxlnx / Athenaion](https://github.com/Leonxlnx/athenaion) の風景と造形を保ちながら、ブラウザでの移動・初回読み込み・メモリ使用を改善する派生版です。原作者は Leonxlnx、ライセンスは MIT です。元の説明は [README.upstream.md](README.upstream.md) に残しています。

元コード: `9b8bd23b39c458a50fb1201037360047781c45b5`。

## 変更内容

- **露出計算を集約。** 全画素で繰り返していた96回の同じ測光サンプリングを、1×1のFloatターゲットで一度計算。最終画素は結果を1回読みます。Float非対応なら元の計算を使用します。アプリ全体が96倍速くなるという意味ではありません。
- **画面の鮮明さを維持。** 高密度ディスプレイの倍率を考慮し、標準設定の移動時解像度は縦横85%を下限にします。旧版の45%まで下げる挙動を修正し、移動中にはFXAAで輪郭を整えます。カメラが止まっていれば、アニメーション中も通常の解像度へ戻します。
- **完成した静止画では描画を休止。** 視点操作・画面サイズ変更・明示的なアニメーションで再開。非表示タブでも休止します。
- **影と水面反射を再利用。** 移動中の更新頻度を抑え、停止時や大きな移動時には更新。ライトと影の対応を保ち、オフライン静止画では各サンプルを更新します。
- **自動トーン測定を間引く。** 移動中原則250ms間隔、停止・最終サンプルでは再測定します。
- **移動中の待ちと不要なコピーを減らす。** 単一フレームをFloat積算バッファへコピーする処理を省き、色調測定は対応環境で非同期取得します。停止後とオフライン出力は元の積算・色調計算を維持します。太陽の可視率も1画素で集約し、参照されない局所色調用の縮小画像は生成しません。
- **静的な座標を再計算しない。** 建物などのローカル行列を確定して再利用します。カメラ・ライト・船・炎の移動、風や鳥のインスタンスアニメーションは維持します。
- **雲・霧だけを半解像度で積分。** 操作中・アニメーション中は、雲と峡谷の霧の重い計算を縦横半分で行い、深度を見て合成します。輪郭で適合するサンプルがない画素、停止後、反射、オフライン出力は元の積分を使います。本体の解像度や元のraymarch回数は下げません。
- **造形を配布前に生成。** 元の生成器で地形・巨像・彫像・瓦礫を事前生成し、gzipで劣化なく配布。大きなバイナリ複製と同じ形状の重複ロードを避けます。
- **植生は最終LODだけ反映。** 元と同じ可視判定・予算調整・LOD履歴を保ち、試行途中の不要なGPUページ作成を除きます。
- **植生の見えないページと不変データを除外。** 風の最大変位まで含む境界で、メイン・反射・各影のカメラごとに除外します。画面外の木の影は維持し、同じinstanceが残るslotは行列・色を再送しません。
- **読み込み失敗を明示。** WebGL非対応や配布データ破損を表示し、宣言済みデータを取得できない場合に重いCPU再生成を始めません。

## 見た目とのトレードオフ

標準は元作品の `quality=preview`。元のdetail/density/terrain設定と、彫刻ライブラリのdetail=1生成を維持します。移動時の解像度・雲・反射や影の更新間隔は変わるため、全フレームの画素が元版と同じという意味ではありません。

| 描画設定 | 静止時の画素上限 PC / モバイル | 移動時の倍率 | 静止積算 PC / モバイル | 移動時AA | 影 |
|---|---:|---:|---:|---:|---:|
| 自動（標準） | 210万 / 100万 | 1.00〜0.85 | 32 / 16 | FXAA | 2048 |
| 画質優先 | 260万 / 150万 | 1.00固定 | 64 / 32 | FXAA | 2048 |
| 軽さ優先 | 110万 / 65万 | 1.00〜0.80 | 16 / 12 | FXAA | 1024 |

倍率は画素予算内の基準解像度に対して縦横に適用します。devicePixelRatioは標準・画質優先で最大2、軽さ優先で最大1.5まで利用し、画素上限を超えないようにします。例えば390×844 CSS px・DPR=3の画面では、標準設定の静止時は679×1471、移動時の下限は577×1250です。モバイル判定はcoarse pointerです。自動調整は約30fpsを目安にしますが、GPU、視点、通信環境に依存し、fpsは保証しません。設定変更ではページを再読み込みします。

## 起動と操作

Node.js 22以降を使用します。

```sh
npm ci
npm run assets
npm run check
npm test
npm run bake
npm run build
npm run verify
npm run serve
```

固定の遠景地形は `npm run assets` が元コミットから取得し、サイズとSHA-256を検証します。既存ファイルも照合します。元の画像・比較資料は原作者のリポジトリを参照し、アプリの動作には使いません。

表示先は `http://localhost:8080/`。`serve` はビルドした `dist/` を配信します。

- ドラッグで回転、ホイールでズーム。右ドラッグまたは2本指で平行移動。
- W A S Dで水平移動、Q Eで上下、Shiftで速く移動。
- 1〜9または風景メニューで撮影地点を選択。
- 「動きをつける」で水・鳥・風などのアニメーションを有効化。
- `?profile=auto|quality|fast`、`?shot=1` で初期設定を指定。

高密度地形も配布する場合は `npm run bake:high` の後にbuildします。標準サイトにはpreview地形だけを収録。存在しないhigh地形へ自動的に切り替えません。オフラインの元レンダリングAPIも残しています。

## GitHub Pages

公開リポジトリの **Settings → Pages → Source → GitHub Actions** を選択します。`main`へのpushで `.github/workflows/pages.yml` が検証・生成・圧縮・公開まで行います。手動実行ではhigh地形も追加できます。

生成物はGit履歴に入れず、生成器の厳密なfingerprintでActionsキャッシュを利用します。Three.jsは同梱し、CDNに依存しません。URLはすべて相対パスで、Pagesの `/repository/` 配下に対応します。

配布するJavaScriptは内容のハッシュを含むディレクトリへ置き、更新時に古いモジュールがブラウザキャッシュから混ざらないようにしています。HTML、通常のimport、動的なモジュール、地形WorkerのURLも検証します。

## 検証と測定の範囲

第2改修では53件の自動テストが成功し、26構成の実GLSLがMesa OpenGL ES 3.2のソフトウェア実装でコンパイル・リンクに成功しました。高密度画面の解像度、アニメーション中の解像度復帰、非同期読み取りの寿命、影を残すカリング、半解像度volumeの状態復元とfallbackを含みます。

| 処理量の比較 | 改修前 | 第2改修後 |
|---|---:|---:|
| 移動フレームのFloat積算コピー | 全画面1回 | 0回 |
| 雲・霧の低解像度積分対象（800×450の例） | 360,000画素 | 90,000画素＋境界の再積分・合成 |
| 植生の予約upload範囲（9視点の移動試験合計） | 221,005,188 B | 70,308,740 B |
| 植生のdraw（9視点、メイン＋影3面の合計） | 3,421 | 3,175 |

植生試験はpreview、1672×941、実配置76,902本、風振幅1、各視点の太陽と3つの影カメラを使い、配置・形状・LOD・行列順・色・影設定を保持して比較しています。upload試験は各視点からカメラを横に0.8mずつ12回移動し、更新間に送信範囲を消費します。これはCPU側で求めた仕事量であり、GPU転送時間やFPSの改善率ではありません。ページをさらに細かく分割する案も調べましたが、削減できる三角形に対してdrawが増えすぎたため採用していません。

ローカルのNode環境で、元の生成器によるpreview地形と全彫刻等、97個のバイナリを生成しました。生成時間は約128秒、raw合計241,323,768 bytesです。独立した2回の生成で96個の新規生成物のSHA-256が一致し、残り1個の遠景地形は上流の固定データを維持しています。これは配布前の処理時間であり、訪問者のブラウザで128秒待つという意味ではありません。

検証内容:

- バイナリのbyte-exact往復、型・正規化・index、共有とclone分離。
- 圧縮配布の展開後SHA-256、破損やHTTP失敗時のエラー処理。
- Workerの失敗・タイムアウト・全pending解決。
- 元の植生実装との21状態の比較。最終LOD、行列、色、履歴、影設定が一致。
- 露出の測光座標・重み・ループ順、offlineのLUTとEMA。
- 影・反射の更新方針、resizeとdispose、例外時の状態復元。
- 実スケジューラーで静止後RAF=0、入力時の再開、非表示タブ、アニメーションの切り替え。
- Pagesのサブパスで全モジュールをHTTP取得し、status/MIME/import解決を確認。

**GPUによる画素比較とFPS改善幅は未測定です。** 開発に使ったクラウドブラウザは `GL_RENDERER = Disabled` でWebGLを作成できません。表示失敗メッセージと再読み込み操作は確認済みですが、実際の3Dが滑らかに動いたという検証結果にはしていません。

比較する場合は、同じ端末・ブラウザ・ウィンドウサイズ・shot・アニメーション設定で元版と比べてください。初回通信とキャッシュ済み再訪を分け、移動中のfpsと停止後の画質を確認します。本版の `window.__PERF` には移動中のフレーム間隔から算出したfps、内部解像度、sample数等を保持します。静止後は描画を休止するため、静止中のfpsは比較対象になりません。

標準配布は圧縮後も大きく、低速回線では初回通信が残ります。詳細な造形を残しているため、すべてのスマートフォンで快適になる保証はありません。
